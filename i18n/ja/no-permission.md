創作物（コードも含みます）を作ると、その著作物にはデフォルトで排他的な著作権が発生します。別段の定めをしたライセンスを含めない限り、ほかの誰も、削除要請や金銭の要求、訴訟のリスクを負わずにあなたの著作物を複製・配布・改変することはできません。著作物にほかのコントリビューター（それぞれが著作権者です）が加わると、その「誰も」にはあなた自身も含まれるようになります。

ライセンスファイルがなくても、利用規約への同意が必要なサイトにソースコードを公開する場合は、一部の権利を許諾することがあります。たとえば、GitHub の公開リポジトリにソースコードを公開すると、あなたは[利用規約](https://help.github.com/articles/github-terms-of-service)に同意したことになり、それによってほかの人があなたのリポジトリを閲覧・フォークすることを認めています。また、[著作権の制限と例外](https://en.wikipedia.org/wiki/Limitations_and_exceptions_to_copyright)がほかの人の個別の状況に当てはまる場合には、その人はあなたの許可を必要としないかもしれません。しかし、サイトの規約も、法域ごとの著作権の制限も、オープンソースライセンスが促すような試行・改変・共有といった、人々が公開コードホストで通常求める種類のコラボレーションには十分ではありません。

ライセンスを提供*しない*ために、何かをする必要はありません。ただし、[利用者](#for-users)があなたの見落としだと思い込まないように、目立つ場所（たとえばプロジェクトの README）に、著作権表示と、いかなるライセンスも提供していない旨の記述を追加するとよいでしょう。ライセンスのないプロジェクトでほかの人からの貢献を受け入れるつもりなら、あなた自身は同じ許可を与えないとしても、コントリビューターからの著作権上の許可を確保できるように、弁護士と相談してプロジェクトにコントリビューター契約を追加することを検討するとよいでしょう。

「ライセンスなし」によってあなたが意図しているのは、コードの利用を禁じることではないかもしれません。[オープンソースライセンス](/)を使えば、著作権を保持したままコードの再利用を認めることができます。著作権による制約から完全に離脱することが目的なら、代わりに[パブリックドメインへの提供](/licenses/#unlicense)を検討してください。

## 利用者の方へ
{: #for-users }

ライセンスのないソフトウェアを見つけた場合、それは一般に、そのソフトウェアの作成者から、ソフトウェアを使用・改変・共有する許可を一切得ていないことを意味します。GitHub のようなコードホストでコードを閲覧・フォークできるとしても、それは、どのような目的であれソフトウェアを使用・改変・共有してよいということを意味するわけではありません。

取りうる選択肢:

{: .bullets}

- **メンテナーにライセンスを追加してもらえるよう丁寧にお願いする。** ソフトウェアにそうでないことを強く示すものがない限り、ライセンスがないのはおそらく見落としです。ソフトウェアが GitHub のようなサイトでホストされているなら、ライセンスを求める issue を作成し、このサイトへのリンクを添えましょう。思い切って行動でき、どのライセンスが最適かがかなり明らかな場合は、ライセンスを追加するプルリクエストを作成しましょう。このサイトの各ライセンスのページのサイドバーにある「このライセンスを提案する」を参照してください（例: [MIT](/licenses/mit/#suggest-this-license)）。
- **そのソフトウェアを使わない。** オープンソースライセンスの下にある代替品を探すか、自分で作りましょう。
- **個別のライセンスを交渉する。** 弁護士を連れて行きましょう。
